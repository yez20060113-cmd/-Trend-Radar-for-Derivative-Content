## 〇、判定对象

判定不是对「一条视频」或「一个事件」做的，而是对**从中抽出的东西**做的。产出分两条线：

```
内容（抖音短视频 / B站视频 / 榜单条目）
   │
   ├─ 抽素材 → 歌 / 模板 / 挑战 ── 聚合 ──► 素材卡（线 A）
   │
   └─ 抽文案 ────────────────── 聚类 ──► 文案簇（线 B）
```

| 线 | 输出单位 | 成立条件 |
|---|---|---|
| **A 素材卡** | 一个可复用的歌 / 模板 / 挑战 | 圈内 `mentions ≥2`；跨圈 `≥3`；圈内榜单新歌零使用也输出 |
| **B 文案簇** | 一句被批量复制的文案（常为歌词） | ≥3 条抖音短视频文案高度相似 |

娱乐事件不输出。它只作为上下文，说明素材为什么火。

---

## 一、三层标签（素材归属用，不用于打分）

| 层级 | 典型内容 | 时间特性 | 作用 |
|---|---|---|---|
| **锚点层** | 人名、团名、歌名、剧名、公司名、CP | 长期稳定 | 定位「这是谁的素材」，**不降级** |
| **时效层** | 挑战名、新歌、事件梗、话题 | 短期 | 判断素材是否刚起来 |
| **形式层** | 直拍、混剪、卡点、变装、4K | 长期泛化 | 只做类型描述，**永不单独触发丢弃** |

锚点层是纵向坐标，时效层是横向信号，两者不可互相替代。

## 二、过滤与门槛（进素材池之前）

两步不在同一个层级，别混：**数据门槛在内容级（采集时）**，**领域过滤在素材级（判定时）**。

**第 1 步 · 领域过滤（素材级）**

在 `judge/material.py` 执行。两条 2026-11-09 定下的规则：

1. **单条样本不足以判死**：硬领域（体育 / 电竞 / 黑名单）要求「**素材名命中**」或「**≥2 条样本命中**」。
   原来把名称 + 3 条样本拼成一段、任意一个词命中就丢，结果《SUPERSTAR》（新歌榜 #7、16 条在用）
   因为一条文案里的「被李秀满淘汰」被判成「体育领域」整卡丢弃。
2. **多义词进软领域**：`淘汰 / 晋级 / 逆转 / 夺冠 / 教练 / 战队 / 小组赛 / 八强 / 四强`
   在选秀、综艺、游戏里太常见，放在 `赛事` 组，需要 ≥2 个词同现才算噪声。
3. **榜单 + 圈内的歌豁免噪声判定**：它是「你关注的人发了什么新歌」，不该被一条评论文案丢掉。

- 体育 / 电竞 / 词库 `噪声黑名单`：**单命中即判噪声**
- 社会 / 时政 / 财经 / 国际：需 ≥2 词命中

⚠️ 英文噪声词必须按**词边界**匹配。`ig` 曾命中 `Highlight`，把 A2O SOUL 的《SUPERSTAR》（新歌榜 #3）整张卡判成「电竞领域」丢弃。

**这一层会误伤，所以有两道事后机制**（2026-11-09 加）：

| 机制 | 做什么 | 触发条件 |
|---|---|---|
| **丢弃留痕** | 每次跑批写 `run_dir/dropped.json`，日报「被丢弃」段按在用条数降序、高证据标 ⚠️ | 每天，零成本 |
| **L3 噪声误伤检测** | 证据 ≥3 条却仍被判噪声（信号自相矛盾）→ 送模型判 keep/drop，keep 免掉噪声判定 | 有矛盾样本才调用，常态 0 |

判据是**矛盾**而不是边界：「差 1 条到门槛」不算矛盾，那是证据不足，模型救不了。
`mentions ≥3` 还被判死才是矛盾——一堆人在用的素材不可能是无关领域。

**第 2 步 · 数据门槛**

| 层 | 规则 | 作用 |
|---|---|---|
| **L0 绝对下限** | 点赞 ≥ 500，且发布时间 ≤ 7 天 | 挡零播放、旧内容 |
| **L1 相对分位** | 点赞进入同批 P40 | 挡"数据平平但被搜到"的 |
| ~~L2 素材型指标~~ | **未接入**：搜索列表页不返回收藏/转发，视频页也未采集 | 暂不生效（不要当成已有能力） |

过 L0 + L1 才进素材池；L2 目前没有可信字段，不做。

## 三、素材抽取（三条规则）

| 类型 | 抽取依据 |
|---|---|
| **歌 / BGM** | 书名号《》、引号「」""，且同现音乐语境（出道曲、新歌、原声、翻跳、卡点…）。**纯英文 token 不再兜底**：搜索结果里的英文串几乎都是团名（#cortis）或账号名（@alekskost），宁可漏不要错 |
| **模板** | **话题标签优先**：`#霸王龙舞步转场挑战#` 整段即成词；无标签时从骨架回溯最多 8 字兜底，并做品牌名（特步/耐克…）、口语前缀（也来/都来/一起…）清洗 |
| **挑战** | 标题本身以「挑战 / 挑战赛」结尾；前缀 2~16 字（`entity.py:_CHALLENGE_RE`），整体 4~18 字 |

反例：

- 引号里若同时出现「剧 / 电影 / 综艺 / 首播」，判为作品名，不当素材。
- **大类概括词不算素材**：`反差变装`、`一键换装`、`变装挑战`、`旅行转场` 这类是分类名，不是某个具体模板，直接丢弃。
- 「教程 / 模板 / 剪同款」属**模板语境**，不是音乐语境——曾因此把 `#cortis` 误判成歌名。

**为什么标签优先**：正则只能从骨架往回数固定字数，「霸王龙舞步」5 个字会被截成「王龙舞步」；而标签的边界天然完整。

## 四、素材卡判定（线 A）

**聚合**：同一素材被多条内容提到 → 合并成一张卡，`mentions` 就是热度证据。

### 4.0 同一玩法先合并，再判定

同一玩法常有多种写法（「霸王龙舞步挑战」33 条 vs「霸王龙舞步转场挑战」9 条）。
不合并会把证据拆到两个词上：两张卡都显得不够格，或者同一批视频被算两遍。

合并规则（`normalize/aggregate.py: merge_variants`）：

1. 先剥掉骨架后缀，得到「玩法本体」：`霸王龙舞步转场挑战` → `霸王龙舞步转场`
2. 一个本体是另一个的**子串**（不要求前缀），且短本体 **≥4 字**、长度占比 **≥0.6**
3. **同类型、同圈层**才合并（模板不会并进挑战）
4. 保留名字更长的那条，短名记进 `variants`

反例（不会被合并）：

| 例子 | 原因 |
|---|---|
| `转场挑战` ⊂ `承诺是你转场挑战` | 剥完只剩空，短本体不足 4 字 |
| `霸王龙步多段转场` vs `霸王龙舞步转场挑战` | 前者是模板，类型不同 |
| `滑镜定格转场挑战` vs `瞬移滑镜慢动作挑战` | 本体互不包含 |

合并后 `mentions` / `anchor_mentions` 相加，链接与样本取并集（上限仍 3 条），
合并进来的写法只是别名，不单独占一张卡。

日报与邮件的证据列会在**有别名时**追加「｜别名：霸王龙舞步挑战」；没有别名则不显示，保持原排版。

### 4.1 先分圈层，再定门槛

素材卡分两类，门槛不同。**不分圈层是此前日报被通用挑战灌满的直接原因。**

| 圈层 | 判定 | 门槛 |
|---|---|---|
| **圈内** | 引用它的内容里 **≥20% 命中主体**（且至少 1 条） | `mentions ≥ 2` |
| **跨圈** | 达不到上面的占比 | `mentions ≥ 3`，且单日最多 3 条 |

输出时两栏分开：`圈内素材（追星垂直）` / `跨圈模板（可套用到追星）`。

**为什么要求占比**：曾有「瞬移滑镜慢动作挑战」33 条在用，其中只有 1 条出现主体（陈少熙 → 十个勤天），
按「任一条命中就算圈内」的旧规则，整张卡被标成「圈内 / 主体=十个勤天」，而它其实是通用转场模板。
现在同时记 `anchor_mentions`，日报里写成「33 条内容在用（含主体 14 条）」，证据强度一目了然。

**主体权重决定「算不算圈内」**（见 `keywords.json` 的 `主体画像`）：

| 档 | weight | 定义 | 是否检索 | 是否算圈内 |
|---|---|---|---|---|
| S | 1.0 | 当打团体、顶流 solo | ✅ | ✅ |
| A | 0.6 | 有稳定二创，量级次一档 | ✅ | ✅ |
| B | 0.3 | 综艺跨界、新团、偶发 | ✅ | ✅ |
| **C** | 0.1 | 大众情怀型（周杰伦、周星驰、四大天王） | ❌ 默认不检索 | **❌ 不算圈内** |

C 档必须排除，否则一条用周杰伦 BGM 的剪辑会把圈内素材挤掉。

**成员名 / CP 只做归因，不单独检索**：命中「宋亚轩」= 命中「时代少年团」；命中 CP 名会记为 CP 锚点。
查询数不增加，但圈层覆盖率提升。

**哪些「名字」不参与判定**（都是实测撞词）：

| 规则 | 例子 |
|---|---|
| 3 字以内英文别名不认（正名除外） | `TNT` / `SM` / `BP` |
| **单字中文别名一律不认** | `礼` 会把「东方礼，送礼就送…」判成 ILLIT |
| 歧义别名需带 `#话题` 或同现正名 | `十七` / `四代` / `三代` / `十八楼` |
| 歧义主体需带限定词 | `染色体` 需同现「家族/舞台/娱乐…」，`SM` 需同现「公司/女团…」 |

### 4.1.1 类型化检索（不同主体找的东西不一样）

| 类型 | 检索式 | 抽取目标 |
|---|---|---|
| 男团 / 女团 | 团体名、`团体 新歌` | 模板 / 挑战 / BGM |
| solo 歌手 | 榜单歌名优先 | BGM |
| **演员** | `姓名 台词` / `名场面` / `转场` | **台词 → 文案层**、BGM |
| rapper | `姓名 beat` / `卡点` | BGM |
| 厂牌 | `厂牌 新团` / `练习生` | 发现旗下新主体 |

配额：主体查询里 **60% 给 S 档、40% 给 A/B 档的演员与 rapper 轮转**。
早期只取 S 档，导致 21 个演员从未被检索过，这条规则等于没写。

演员的剧本台词不进素材卡（素材卡一天只有 8 张），而是送到「复用短语 / 文案簇」那条线——
台词就是被批量复制的文案。

### 4.2 圈内新歌：零使用也输出

| 条件 | 结果 |
|---|---|
| 来自**新歌榜 / 飙升榜** + 歌手是你关注的主体 | ✅ 输出，即使抖音暂无使用记录 |
| 来自**热歌榜** | 走普通门槛（`mentions ≥ 2`）——热歌榜是存量热度，一首老歌不该按「新歌」进日报 |

理由：「某艺人发新歌」本身就是可行动信息，拿它做视频自带流量。
这种情况下 `mentions` 表示「抖音上有多少条内容提到这首歌名」，不等于真实使用量（见 4.6）。

### 4.3 其余规则

| 条件 | 结果 |
|---|---|
| 圈内 `mentions ≥ 2` | ✅ 输出 |
| 跨圈 `mentions ≥ 3` | ✅ 输出 |
| 圈内 `mentions = 1` + 首见 ≤7 天 + **来自抖音热榜** | ✅ 输出（榜单即"当下在火"的旁证） |
| 其余 | ⚪ 候选池 |
| 抽不出具名素材 | ❌ 丢弃 |

**排序与配额**：

- 排序：`mentions×4 + 跨平台×2 + 圈内4 + 时效3 + 榜单加成(3/1) + 词龄权重(0~3) + 播放`
  （不按类型优先；早期「BGM → 模板 → 挑战」的硬排序会让零使用的歌压掉在用挑战）
- 同一主体单日最多 2 条（`judge.per_anchor_cap`）
- 圈内单日上限 8 张（`judge.max_hotspots`），跨圈 3 张（`judge.max_cross`）

**模板词龄权重**（参与打分，不参与门槛）：距首见 ≤7 天 3 分 / 8~30 天 2 分 / 31~60 天 1 分 / >60 天 0 分。

### 4.3.1 跨天复用治理（2026-11-09）

背景：11-06~09 的日报里 11 个位置有 8 个在复用（NEON、我要逮捕你、瞬移滑镜…）。
原因是「计划 → 采集 → 判定」三层都没有新鲜度约束：挑战查询 100% 来自上一轮，
歌名跟着榜单走，判定只看 mentions（老卡基数大，永远压过新卡）。

现在判定前先读最近 `repeat_window_days`（默认 4）天的 `data/daily/<日期>/materials.json`，
得到每张卡「连续第几天」与上次的 mentions：

| 条件 | 处理 |
|---|---|
| **连续第 4 天**（已连续出现 3 天）且 mentions 涨幅 <20%（非榜单卡） | **让位**：降为候选，理由写「让位给新素材」 |
| **榜单 BGM** | **不按计数判衰退**（覆盖度波动会造成假性下跌），只受下方额度约束 |
| 昨日已出现过（连续 1~3 天） | 标记 `repeat`，最多保留 **3 张**（`max_repeat_cards`），超出降为候选 |
| 从未出现 | 不受限 |

报告证据列会写「连续第 N 天（仍在榜）」或「连续第 N 天（热度上升）」，**复用与新面孔一眼可分**。

### 4.4 BGM 从哪来

抖音网页版**不暴露** `music` 字段，五条路全部实测排除：

| 路径 | 结果 |
|---|---|
| 视频页 DOM / `iesdouyin` 分享页 / `RENDER_DATA` | ❌ 无 music（RENDER_DATA 里的 "music" 是搜索卡片配置） |
| 搜索 `type=music` | ❌ 0 条结果，没有音乐类目 |
| `douyin.com/music`、`/hot/music` | ❌ 404 / 视频不存在 |
| 汽水音乐 Web | ❌ 只有下载落地页 |
| **QQ音乐榜单** | ✅ 有歌名+歌手+排名 |

所以 BGM 分两条供给：

| 来源 | 能给什么 | 成本 |
|---|---|---|
| **QQ音乐榜单**（主） | 「你关注的艺人发了什么新歌」+ 歌名词典 | 0 |
| **SandBase 采样**（补） | 每条视频真实 `music.title / author` / `is_original_sound` | 100 次/天免费 |

⚠️ **`user_count` 恒为 0**：该 endpoint 不填使用人数，`music_chart_ranks` 也是 null。
所以「全平台多少人用过」这个数拿不到，只有歌名/歌手/是否原声。

### 4.5 BGM 采样：按素材，不按视频

**BGM 是素材的属性，不是视频的属性。** 创作者问的是「这个挑战配什么歌」，不是「这条视频配什么歌」。

三层省钱逻辑（`src/collectors/bgm_sampler.py`）：

| 顺序 | 判断 | 结果 |
|---|---|---|
| 1 | 素材类型是 BGM | 跳过（本身就是歌） |
| 2 | 素材名 / 文案里命中同一首榜单歌 | **直接推断**为该素材配乐，不花配额 |
| 3 | 该素材已在缓存（默认 7 天有效） | 复用 |
| 4 | 其余 | 取互动最高的代表视频调用接口，受 `daily_budget` 约束 |

**占位结果不入日报**：`模板音乐 / 模板创作人`、`@某某创作的原声` 是剪映模板与原声的通用占位，
实测两个不同挑战会返回**同一个 music_id**。这类结果只写缓存（带 `placeholder` 标记）防重复花配额，
但不会覆盖素材的配乐字段——日报里宁可空着，也不写「配乐：模板音乐」。

采样单位：**每个素材 1 条代表视频**（`per_material: 1`）。
预算默认 60 次/天（免费额度 100），但它是**上限不是目标**：稳态实测多为 **0 次**
（热点素材里大半本身就是歌、或已命中缓存/推断），只有出现 3~5 个**新**热点素材时才会花 3~5 次。

**没有 key 时**：只输出采样计划（`sandbox/runs/<ts>/bgm_plan.json`），不报错、不影响日报。

### 4.6 一个必须说清的口径

- 模板 / 挑战卡上的 `mentions` 是「多少条视频在用这个玩法」，真实。
- BGM 卡上的「N 条内容提到该歌名」只是**提到**，不是使用量——视频实际用了什么配乐，网页版读不到。
- 只有走过 SandBase 采样、且不是占位的素材，才在日报里显示「配乐：XXX（接口）」。

## 四·五、检索计划（词库的角色变了）

词库**不是检索白名单**，是「这个领域长什么样」的参照。原因很简单：
词库永远追不上新团、新歌、新挑战，把它当白名单用，漏掉的比抓到的多。

所以检索拆成两层：

| 层 | 谁来做 | 产出 |
|---|---|---|
| **计划层** | 模型（或规则版脚本）+ 榜单 + 热榜 + 上一轮结果 | `data/input/query_plan.json`，30~40 个查询 |
| **执行层** | `collect_douyin.py`（CDP，零 token） | `data/input/douyin_latest.json` |

查询分四类，各有配额：

| 类型 | 来源 | 默认配额 |
|---|---|---|
| 歌名 | 音乐榜单 ∩ 主体 | 15 |
| 挑战/模板 | 热榜里以「挑战」结尾的标题（**实测很少，多数为 0**）+ 上轮结果补齐 | 10 |
| 主体 | S 档 60%（6 个/天，49 个 ≈ 8 天一轮）+ A/B 档演员与 rapper 40%（4 个/天，28 个 ≈ 7 天一轮） | 10 |
| 发现 | 上轮生命周期里的新词（≥4 字、出现 ≥2 次、不是更长词的截断片段） | 5 |

**词库在检索后的作用不变**：仍用来判断圈层（圈内 / 跨圈），这一层不动。

**顺序是交错的**，不是「一类跑完再下一类」。2026-11-09 的计划是「歌名 10 → 挑战 10 → 主体 10 → 发现 5」，
采集在第 10 个查询后就开始 502，结果 8 张卡全是 BGM、跨圈 0——不是当天没有新挑战，而是挑战查询根本没轮到。
现在按 `歌名 → 挑战 → 主体 → 发现` 轮流取，同样的覆盖率会得到各类型都有的样本。

执行层硬性要求（不加就会撞风控）：

1. 查询间随机间隔 **8~15 秒**（`delay_min`/`delay_max`）。2026-11-07 实测：3~6 秒时第 16 个查询起全空，疑似会话级限流，故调慢；调慢后单轮约 25~30 分钟
2. 失败指数退避（5s→15s→45s）；`NEED_LOGIN` 与其他错误**分开**——前者重试后仍失败就中止整轮，
   后者只记该查询失败、继续下一个
2b. **502 单独处理**：退避 30/90/180 秒，且**不计入空结果熔断**；连续 3 个 502 触发一次 180 秒冷却，
   冷却 2 次仍不恢复才中止。依据：2026-11-09 的失败截图是 `502 Bad Gateway / kngx`，
   网关故障按分钟恢复，5/15/45 秒等于没等
3. **每查完一个就落盘**，中断后 `--resume` 续采（只跳过成功项，失败项会重试）
4. 连续 N 个「空结果 / 解析为空」先**原地冷却**（`empty_cooldown_s`，默认 240 秒，最多 2 次），
   仍无改善才中止（`--max-empty`）。依据：2026-11-09 实测这类空结果是**间歇性软拦截**
   （搜索页停在骨架屏，无验证码），一个窗口能采 3~9 个查询，几分钟后自行恢复；
   直接退出会让整轮只剩 3~4 个查询
5. **每 12 个查询换一次页签**（`--page-recycle`）：单页签连开几十个搜索页会把渲染进程撑爆。
   页签丢失时按 5/10/15 秒等待后重建并重试当前查询（最多 3 轮）；3 轮都失败则保存已采部分、
   退出码 4，由 `daily_run` 换新进程 `--resume` 续采
5b. **默认整页加载，页内改词是实验开关（`--spa`，默认关闭）。**
   改词能把单查询请求从 ≈517 降到 ≈138（降 73%），但 2026-11-09 实测它会**丢掉 `publish_time` 过滤**：
   「一键换装」76 条里 60 条超过 7 天，而整页版是 0 条。
   换句话说，省下的请求是拿时效质量换的，所以默认不用；只有在 502 窗口内做抢救式采集时才值得开
   （`--spa --scroll 8`）。改词的判据必须等到「结果节点被替换」，拿不到就退回整页——
   宁可贵 300 个请求，也不读旧结果
6. **每行日志带 `耗时 / 模式 / conn / pages`**：`conn=False` 说明 CDP 会话被回收，
   `conn=True pages=0` 说明只是页签被丢弃；`模式` 是「改词 / 整页」。
   查询记录里另有 `aged_out`（超出时间窗的条数），用来监控改词有没有带来时效退化
7. **整页被挡时改词救急**：整页 15 秒拿不到卡片、又不是 502 时，用页内改词再取一次；
   救急结果按 `publish_time` **过滤超窗条目**后才入库（改词会丢时间过滤，不能直接采信）
8. **覆盖率不够不算采完**：`daily_run` 在采集进程正常退出后检查「成功数 / 计划数」，
   低于 `min_coverage`（默认 70%）就等 `coverage_wait_s`（240 秒）再 `--resume`，
   最多 `collect_retries`（4）次。否则「进程成功退出但只采到 4 个」会被当成跑完，
   发出一封 26% 覆盖率的日报

## 五、文案簇判定（线 B）

**为什么单独成线**：这类热点的载体不是歌、不是模板，而是一句话。它天然跨领域（旅行、摄影、体育都在用），**跨领域复制恰恰是它成立的证据**。

### 5.1 三道准入闸门（缺一个就会出假阳性）

| 闸门 | 规则 | 挡掉什么 |
|---|---|---|
| **不是宣发贴** | 中文字符 ≥8；中文占比 ≥60%；不含 `w/` | `to the moon :) w/ #艺人A` × 4 条曾被判成文案簇，实际是同一首歌的多组联名宣发 |
| **不是同一素材** | 正文命中榜单歌名 / 素材名 → 归素材卡，不算文案梗 | 把歌曲宣传当成「文案被复制」 |
| **还活着** | 成员发布时长中位数 ≤7 天 | 宣传期残留（10-23 发的歌，11-06 还在输出） |

再加两条原有门槛：**≥3 条**、**≥2 个不同作者**（挡同一账号刷同款）。

### 5.2 相似度

1. 只取抖音短视频（B站长标题多为同一事件的不同描述，会误聚）
2. 文案归一：去 #标签、@作者、emoji、标点
3. 字符 3-gram **包含度** = |A∩B| / min(|A|,|B|)，阈值 0.55

### 5.3 已否决的方案：改走话题页

实测 `#话题` 搜索与普通搜索返回**完全一样的 26 条、0 重复**（承诺是你转场挑战、滑镜定格转场挑战各测一次）
——搜索页对相似内容做了打散，话题搜索也不例外。**这条路不通，不要再试。**

### 5.4 复用短语（发现线索，不是热点）

整句聚类只能抓「一字不差」的复制，抓不到「半句相同、后半句各写各的」这类变体。
所以另做一层短语统计：4~10 字中文短语，出现在 ≥3 条**不同视频**里 → 列为线索，不进热点。

这一层最容易出假阳性（「影之刃零」是游戏名，曾被当成文案梗），所以有两道过滤：

**B 规则层（零 token）** —— `src/judge/works.py`

| 判据 | 规则 |
|---|---|
| 作品语境 | 短语的来源文案里 ≥60% 命中作品词（副本/BOSS/攻略/全收集/预告/定档/新番/正片…） |
| 句子形态 | 短语本身含人称/语气/动作词（我/你/的/了/吗/不/很…）→ 判定它像句子，不算专名 |

两条**同时**成立才判专名剔除。验证：「影之刃零」语境比 1.0 → 剔除；「世界如此辽阔」语境比 0.0 → 保留。

**D 标签层（模型判定，每天一次）** —— `data/state/phrase_labels.json`

```json
{"影之刃零": "title", "打歌舞台": "noise", "世界如此辽阔": "copy"}
```

- 管线每轮把**未经判定**的短语写进 `sandbox/runs/<ts>/phrases_todo.json`
- 由模型（或人）判定后写入标签文件，下一轮生效
- `copy` 直接放行并跳过 B 规则；`title` / `noise` 直接剔除

**为什么需要 D**：规则只能靠词表，追不上新游戏、新番、新剧。而这层判断只需要每天 10 条、约 1k tokens。

**为什么不只靠 D**：规则能挡掉 80%，且零成本、无延迟；模型只处理剩下的边界情况。

工作流：
```bash
python scripts/review_phrases.py                       # 看待判定
python scripts/review_phrases.py --auto                # 让模型批量判（2026-11-09 接通）
python scripts/review_phrases.py --label 影之刃零=title  # 人工改判，随时可覆盖
```

`--auto` 走的是 `src/llm/phrases.py`：把整批 `phrases_todo.json` 一次喂给模型，
它只能判 `copy / title / noise` 三选一，且短语必须**一字不差**来自输入
（防止它顺手「纠正」断句残片）。结果仍写同一个 `phrase_labels.json`，链路不变。
模型不可用时自动退回人工 `--label`，不阻塞跑批。

**可用性评估（2026-11-10 加，与上面的标签判定是两件事）**

| | 标签判定 `label()` | 可用性评估 `evaluate()` |
|---|---|---|
| 目的 | 数据清洁：这句话能不能留在候选池 | 产品判断：留下来的能不能用、怎么用 |
| 结果去向 | `phrase_labels.json`（长期，下一轮生效） | 当天日报「今日可用文案」栏 |
| 错了的代价 | 会长期污染候选池 | 只是当天少一条 |

判据只有一条：**脱离原语境，这句话还能不能用来描述「追星 / 偶像 / 成长 / 情感」**。

- `use` → 进日报主表，带「怎么用 / 出处 / 配套素材」
- `watch` → 进「观察中」，标注需要改写的点
- `skip` → 不显示（例如「王源新歌」「XX生日」这类描述性短语）

原句必须一字不差来自输入，改过的句子一律丢弃——模型爱「顺手润色」，润色过的话就是它编的。
同时会尝试关联当日热点素材：如果这句出现在某条文案里、而那条文案又提到今天的素材名，
就把那个素材写进「配套素材」列（例：`把天看破` → `管他的公路尽头`）。

## 六、判定原则

- **不做关键词一票否决**：一条内容常带多个标签，形式标签不构成否决。
- **锚点不降级**：主体名是长期坐标，不因时效逻辑被降权。
- **候选不是判死**：证据不足的素材留池，下一轮重新判定。
- **形式词不独立判定**：直拍 / 混剪 / 卡点单独出现时信息不足，永不据此丢弃。
- **量化优先于文本**：发布时间、点赞、收藏率 优先于标题里的「新歌 / 回归」等词。
