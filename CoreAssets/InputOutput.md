## 一、输入

### 1.1 输入形态

**抖音搜索（主）**：由 Agent 用浏览器（Edge，带登录态）采集，落成 `data/input/douyin_latest.json`，管线读取。

```json
{"collected_at": "...", "source": "plan", "plan_total": 40,
 "queries": [{"q": "A2O LITE", "publish_time": 7, "items": [
   {"url": "...", "text": "文案 #标签", "likes": 74000, "age_days": 3}],
   "error": ""}]}
```

- `plan_total`：本轮**计划**跑多少个查询。中途被限流中止时，它就是分母，
  管线据此在邮件里写「仅覆盖 15/33 个查询」。没有它，「提前中止」会被误当成「全部完成」。
- `error`：单个查询的失败原因（`空结果` / `解析为空` / `NEED_LOGIN` / 异常摘要）。
  非空即视为失败，`--resume` 会重试这些查询。

采集规则：搜索 URL 默认带 `publish_time=7`（一周内）；查询由 `data/input/query_plan.json` 给出，
分**榜单歌名 / 挑战模板 / 主体 / 发现**四类（每类有配额），不要「主体 × 混剪」这种组合（实测无结果）。
每个查询滚动 5 屏（实测约 50 条），查询间隔 8~15 秒（防会话级限流），逐查询落盘可 `--resume`。

**QQ音乐榜单（BGM 主源）**：`https://y.qq.com/n/ryqq/toplist/<id>`，服务端渲染，免登录。
默认抓三个榜（`sources.qq_music.charts`）：`27` 新歌榜 / `62` 飙升榜 / `26` 热歌榜，
同名歌曲按出现顺序去重（先出现的榜名生效）。

```json
{"songs": [{"name": "NEON", "artists": ["A2O LITE", "A2O"], "rank": 2,
            "url": "...", "chart": "新歌榜"}],
 "charts": ["新歌榜", "飙升榜"], "errors": []}
```

- `chart`：这首歌来自哪个榜。**「今日新歌」只收新歌榜 / 飙升榜**，热歌榜是存量热度，不算新歌。
- 没有 `trend`：JSON-LD 不提供排名升降，所以模型里也不再保留这个字段。

- 解析方式：页面内嵌 JSON-LD（schema.org `MusicRecording`），结构稳定
- 用途：与 `锚点层.主体` 求交集 → 「你关注的艺人发了新歌」；歌名同时作为抖音文案匹配的词典
- 局限：拿不到抖音真实使用量，只能统计「多少条内容提到该歌名」

**其他来源**：

- **榜单条目**：抖音热榜的标题（模板/挑战名字的来源之一）。
- **B站视频对象**：标题 + 标签 + 播放/点赞/评论 + 发布时间（交叉验证用，无 BGM 字段）。
- **抖音 `music` 字段**：❌ 网页版不暴露（视频页 / 分享页 / RENDER_DATA 三条路均已实测排除）。


### 1.2 字段在判定中的用途

| 字段 | 用途 | 对应环节 |
|---|---|---|
| `likes`（点赞） | L0 绝对下限 + L1 同批分位 | 数据门槛 |
| `age_days`（发布距今天数） | 时效硬门槛（>7 天丢弃） | 数据门槛 |
| `collect_rate` / `share_rate` | L2 素材型指标 —— **未接入**（列表页拿不到藏/转） | 暂不生效 |
| `play`（播放量） | 热度基数，参与素材打分 | 素材热度 |
| 标签 / 话题 | 锚点归属 + 反推歌名（文案簇的标签常带歌名） | 抽取 / 聚类 |
| `music`（BGM） | **未接入**；接入后作为 BGM 强证据 | — |

> 抖音搜索列表只给点赞，拿不到收藏/转发；视频页也没有采集，所以 L2 门槛**尚未接入**。
> 门槛参数在 `config/sources.yaml` 的 `threshold` 段（min_likes / max_age_days / percentile）。

## 二、关键词库怎么用

### 2.1 路径与读取

- 路径：`CoreAssets/keywords.json`
- 读取方式：`json.load`
- 顶层结构：`锚点层`（主体 / 主体画像 / 成员归属 / 厂牌 / CP / 歌名 / 剧名）/ `时效层` / `形式层` / `模式层` / `领域种子词` / `别名映射` / `噪声黑名单`

### 2.2 三层对应关系

| 词库字段 | 用途 | 状态 |
|---|---|---|
| `锚点层.主体` | 圈层归因 + 主体检索池 | ✅ 生效 |
| `锚点层.主体画像` | tier / weight：决定是否检索、是否算圈内 | ✅ 生效 |
| `锚点层.成员归属` | 成员名 → 团体（`宋亚轩` = 时代少年团） | ✅ 生效 |
| `锚点层.厂牌` | 厂牌 → 旗下艺人（`build_keywords.py` 生成） | ⚪ **预留**：没有任何代码读这个映射。计划层只按 `主体画像.type == "厂牌"` 给主体加「新团/练习生」限定词，与厂牌映射无关 |
| `锚点层.CP` | CP 名参与锚定（**不进搜索**，两个艺人一起搜会污染） | ✅ 生效 |
| `别名映射` | 别名归一化（单字 / 3 字英文别名受限） | ✅ 生效 |
| `模式层.模板骨架` | 抽模板名（`{X}变装`…），非词表匹配 | ✅ 生效 |
| `模式层.骨架校验词` | 防止「挑战极限」这类误召回 | ✅ 生效 |
| `模式层.已知实例` | 带首见月份的旧模板样本，用于词龄校准 | ✅ 生效 |
| `噪声黑名单` | 素材级过滤，单命中即判噪声 | ✅ 生效 |
| `锚点层.歌名` / `剧名` | 预留（当前为空，代码不读） | ⚪ 预留 |
| `时效层.热点信号词` | 预留（时效目前用点赞/发布时间/榜单判断） | ⚪ 预留 |
| `形式层.创作类型词` / `场景词` | B站组合搜索 + 复用短语排除 | ✅ 生效 |
| `领域种子词` | 预留（当前不用于粗搜） | ⚪ 预留 |

### 2.3 写回规则（自动生长，**当前暂未实现**）

- 发现新主体 → 追加到 `锚点层.主体`
- 发现新歌名 / 剧名 → 追加到 `锚点层.歌名` / `剧名`
- 发现新别名 → 追加到 `别名映射`
- 发现新噪声词 → 追加到 `噪声黑名单`
- 写回前先去重；不覆盖人工维护的内容。

## 三、输出

### 3.1 判定的单位是「素材」，不是「内容」

一条视频不是输出，一个事件也不是输出。**只有从内容里抽出来的可复用素材才算输出单位**：

| 素材类型 | 定义 | 例 |
|---|---|---|
| **BGM** | 一首可拿来配乐/卡点的歌 | NEON、Whiplash |
| **模板** | 一套可套用的剪辑/拍摄套路 | 7套换装、凤凰神女仿妆 |
| **挑战** | 一个有参与入口的挑战玩法 | 霸王龙舞步转场挑战 |

娱乐事件不输出。它只作为上下文，说明这个素材为什么火。

### 3.2 素材卡格式

```json
{
  "素材": "NEON",
  "类型": "BGM",
  "可用于": ["卡点", "挑战拍摄", "配乐"],
  "主体": "A2O LITE",
  "证据": "42 条内容在用（含主体 21 条）",
  "配乐": "（可选）该素材的 BGM，仅有真实采样时才有",
  "变体": ["霸王龙舞步挑战"],
  "链接": ["https://www.douyin.com/video/7703112097772637480"]
}
```

- **素材**：具名实体，必须能被单独检索到
- **类型**：BGM / 模板 / 挑战
- **可用于**：由类型直接映射，不需要模型自由发挥
- **证据**：被多少条内容提到 + 其中多少条真的命中主体 + 首见天数（不是"热度值"）。BGM 卡写「N 条内容**提到**该歌名」，不写「在用」
- **变体**：被合并进来的其他写法（同义简写），可为空；合并规则见 `HotspotCriteria.md` 4.0
- **链接**：最多 3 条参考

### 3.3 不进输出的东西

| 内容 | 去向 |
|---|---|
| 娱乐事件 / 资讯 | 仅作上下文，不输出 |
| 只有一条引用、且不是榜单来源 / 圈内榜单新歌的素材 | 候选池 |
| 抽不出具名素材的内容（合集、泛词、vlog） | 丢弃 |
| 社会 / 体育 / 时政 / 电竞 | 丢弃 |

### 3.4 示例

输入：`【4K舞台】…A2O LITE出道曲「NEON」打歌舞台+直拍合集`
输出：`{"素材":"NEON","类型":"BGM","可用于":["卡点","挑战拍摄","配乐"],"主体":"A2O LITE","证据":"3 条内容提到该歌名","链接":[...]}`

输入：`【A2O MAY】出道前考古…`
输出：（抽不出具名素材，丢弃）

输入：`霸王龙舞步转场挑战`
输出：`{"素材":"霸王龙舞步转场挑战","类型":"挑战","可用于":["参与挑战","套用玩法"],"主体":"","证据":"1 条内容在用，来自榜单","链接":[]}`

### 3.5 文案簇（与素材卡并列的第二类输出）

同一句文案被多条短视频复制 → 一条「文案模板」。常为歌词，标签里往往带歌名。

```json
{
  "文案": "世界如此辽阔 请不要走进悲伤角落",
  "规模": 6,
  "最高赞": 345000,
  "中位赞": 39000,
  "相关标签": ["赛里木湖", "祁飘", "风和自由"],
  "变体": ["世界如此辽阔，请不要走进悲伤的角落", "你看 世界如此辽阔 请不要走进悲伤角落"],
  "参考": ["https://www.douyin.com/video/..."]
}
```

判定：同一批抖音短视频里，文案归一化后字符 3-gram 包含度 ≥0.55、成簇 ≥3 条。
B站长标题不参与（多数是同一事件的不同描述，不是文案梗）。

### 3.6 一次跑批产出哪些文件

所有产物写 `sandbox/runs/<时间戳>/`，**不直接写 `data/daily/`**——那里只收真正发出去的日报
（由 `daily_run.py` 在邮件发出后归档）。

| 文件 | 内容 | 谁读它 |
|---|---|---|
| `report.md` | Markdown 日报（人看的主产物） | 人 / 邮件附件 |
| `materials.json` | 全部素材卡，含 `cls`（热点/候选/丢弃）与 `reason` | 次日跨天复用治理、回放脚本 |
| `candidates.json` | 去重后的全部内容（418 条这个量级） | 离线回放、排障 |
| `dropped.json` | **全部被丢弃的素材**：在用条数 + 原因 + 样本 + 模型裁决 | 复盘词表误伤；`high_evidence` 就是报警依据 |
| `report_data.json` | 文案簇 / 复用短语 / 今日新歌（渲染邮件用的旁路数据） | 邮件渲染 |
| `meta.json` | 耗时、各源状态、模型层统计 | 排障 |
| `llm_material.json` | L2 抽出的素材 + 证据 + 置信度 + 被拒原因（证据不实/名字不合规） | 评估 L2 效果 |
| `llm_verdicts.json` | L3 的 keep/drop 明细与矛盾理由 | 评估 L3，解释「为什么这张卡被救回」 |
| `phrase_eval.json` | 文案可用性评估：原句 / use-watch-skip / 怎么用 / 出处 / 关联素材 | 复盘「今天哪些句子真的能用」 |
| `data/input/hot_seeds.json` | 聚合榜筛选结果 + 生成的查询词（不在 run 目录，是计划的输入） | `plan_queries.py` 读它，生成「热种」类查询 |
| `llm_calls/NNN-<层>.json` | 每次模型调用的耗时、token、完整请求/响应 | 模型出问题时的唯一证据 |
| `bgm_plan.json` | BGM 采样计划与跳过原因 | 采样配额排查 |

`dropped.json` 的结构：

```json
{
  "total": 12,
  "high_evidence": 1,
  "items": [
    {"name": "后会友期", "type": "BGM", "mentions": 3, "circle": "跨圈",
     "reason": "电竞领域（电竞）", "llm_verdict": "", "samples": ["...", "..."]}
  ]
}
```

**`high_evidence` 是最该看的数字**：它统计「≥3 条内容在用、却被判噪声」的素材。
大于 0 说明噪声词表可能误伤了——2026-11-09 早上的《SUPERSTAR》（16 条在用被判体育领域）
就是这一类，当时只能靠人翻日志才发现。
