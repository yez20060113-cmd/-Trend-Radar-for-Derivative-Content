# 关键词库模板

> 仓库里**不包含** `CoreAssets/keywords.json`——它含具体的主体名单和别名映射，
> 属于使用者自己的运营资产。这里给的是**结构和填法**。
>
> 用法：把下面的 JSON 骨架复制成 `CoreAssets/keywords.json`，按需填词。
> 程序启动时从这里加载；文件缺失会直接导致计划为空、采集 0 条。

---

## 一、结构总览

```json
{
  "锚点层": {
    "主体": [],
    "CP": [],
    "歌名": [],
    "剧名": [],
    "主体画像": {},
    "成员归属": {},
    "厂牌": {}
  },
  "时效层": {
    "热点信号词": []
  },
  "形式层": {
    "创作类型词": [],
    "场景词": []
  },
  "模式层": {
    "模板骨架": [],
    "骨架校验词": [],
    "自带校验骨架": [],
    "已知实例": {}
  },
  "领域种子词": [],
  "别名映射": {},
  "噪声黑名单": []
}
```

七个顶层字段各管一件事，下面逐个说。

---

## 二、锚点层：长期坐标

「谁是我们要追的人」。这一层决定检索计划的主体配额，也决定「圈内 / 跨圈」怎么分。

### `主体`

追踪对象的名字，字符串数组。

```json
"主体": ["<团体名>", "<个人名>", "<组合名>"]
```

**填多少**：建议 20~50 个。太少则每天重复，太多则轮转周期过长
（每天只抽 10 个主体，112 个主体要 11 天才轮一遍）。

### `主体画像`

每个主体的属性，决定它的权重和检索优先级。

```json
"主体画像": {
  "<主体名>": {
    "tier": "S",
    "weight": 1.0,
    "region": "内娱",
    "type": "男团",
    "org": "<所属公司>"
  }
}
```

| 字段 | 取值 | 作用 |
|---|---|---|
| `tier` | `S` / `A` / `B` / `C` | 分档。**C 档默认不进检索计划**，只在热榜/榜单命中时使用，避免挤占圈内名额 |
| `weight` | 0.0~1.0 | 排序权重，影响同分时的先后 |
| `region` | `内娱` / `韩娱` / `日娱` … | 用于分组统计 |
| `type` | `男团` / `女团` / `个人` / `演员` … | 决定查询模板（团体搜「组合名+挑战」，演员搜「剧名+名场面」） |
| `org` | 公司名 | 与 `厂牌` 对应，用于识别同公司联动 |

### `成员归属`

团体 → 成员列表。用于「搜团体名时也能命中成员名」。

```json
"成员归属": {
  "<团体名>": ["<成员甲>", "<成员乙>"]
}
```

### `厂牌`

公司 → 旗下团体。用于同公司交叉推荐。

```json
"厂牌": {
  "<厂牌名>": ["<团体A>", "<团体B>"]
}
```

### `CP` / `歌名` / `剧名`

```json
"CP": ["<甲×乙>"],
"歌名": [],
"剧名": []
```

`歌名` 和 `剧名` 是人工补充的强信号词，可以留空——榜单和搜索结果会自动覆盖大部分。
`CP` 用来生成 CP 向查询；不填则跳过这类查询。

## 三、时效层：判断「新不新」

```json
"热点信号词": ["挑战", "新歌", "回归", "官宣", "定档", "上线", "爆火", "翻红", "首发", "大赏"]
```

出现在文案里，说明这条内容有时效性。**判定「是不是热点」靠它**，不靠点赞数。

留空会导致所有素材都判成「没有时效证据」，全部进候选池，日报为空。
所以这一层**建议保留默认值**。

---

## 四、形式层：判断「能不能当素材」

```json
"创作类型词": ["混剪", "转场", "卡点", "变装", "仿妆", "直拍", "应援", "手书", "同人"],
"场景词": ["打歌舞台", "签售", "演唱会", "音乐节", "见面会", "生日会"]
```

| 字段 | 用途 |
|---|---|
| `创作类型词` | 说明「这条内容是什么形式的二创」。形式词本身**永不单独触发丢弃** |
| `场景词` | 说明「在哪发生的」。与主体名同现时，用来判断圈内/圈外 |

---

## 五、模式层：抽取「模板/挑战」类素材

这一层决定能不能抓到 `某某变装` `某某转场挑战` 这类玩法。

```json
"模板骨架": ["{X}摇", "{X}手势舞", "{X}变装", "{X}换装", "{X}转场", "{X}转场挑战", "{X}挑战", "{X}特效", "{X}滤镜", "{X}仿妆", "{X}卡点", "{X}合拍"],
"骨架校验词": ["教程", "模板", "一键剪同款", "剪同款", "拍同款", "跟拍", "合集", "挑战赛"],
"自带校验骨架": ["变装", "换装", "转场", "转场挑战", "手势舞", "仿妆", "卡点"],
"已知实例": {
  "<玩法名>": "YYYY-MM"
}
```

| 字段 | 作用 |
|---|---|
| `模板骨架` | `{X}` 是占位符，匹配「任意词 + 后缀」。**留空 = 抓不到模板/挑战类素材** |
| `骨架校验词` | 骨架命中后，需要附近出现这些词才确认是玩法（防止「某某挑战杯」这种误判） |
| `自带校验骨架` | 这些后缀本身足够强，不需要额外校验词 |
| `已知实例` | 记录已验证的玩法名 + 首见月份，用于跨天去重和「老梗让位」 |

---

## 六、领域种子词

```json
"领域种子词": ["女团", "男团", "KPOP", "内娱", "打歌舞台", "饭制"]
```

用来一次性召回整个领域的泛词。**不参与判定**，只用于扩展检索。

---

## 七、别名映射

主体 → 它的其他写法。**决定了跨天复用统计准不准**。

```json
"别名映射": {
  "<主体名>": ["<英文名>", "<缩写>", "<常见误写>", "<粉丝昵称>"]
}
```

为什么重要：跨天复用靠名字对齐。如果同一主体今天写「A2O LITE」、明天写「A2O」，
不填别名就会被当成两个不同的主体，复用额度和热度趋势都会算错。

**建议每个主体至少填 1~2 个高频别名。**

---

## 八、噪声黑名单

```json
"噪声黑名单": ["<需要排除的泛词>", "<容易误判的领域词>"]
```

命中即判噪声丢弃。这里放的是「看起来像素材、实际不是」的词，
比如各类活动的通稿名、非追星领域的专有名词。

⚠️ **小心多义词**：像「淘汰」「晋级」这类词在选秀、综艺、游戏里都常见，
放进黑名单会误伤。这类词应该走「需要 ≥2 个词同现」的软判定，而不是一票否决。

---

## 九、最小可用集

只想先跑起来，按这个填：

| 字段 | 最低要求 | 不填的后果 |
|---|---|---|
| `主体` | **≥1 个** | 计划为空，采集 0 条，日报空 |
| `主体画像` | 建议填，可留空 | 排序权重一致，C 档过滤失效 |
| `别名映射` | ≥1 条 | 跨天复用统计不准 |
| `热点信号词` | **建议保留默认** | 全部判成「无时效证据」→ 全进候选 |
| `创作类型词` | 建议保留默认 | 圈内/跨圈判断退化 |
| `模板骨架` | 可留空 | **抓不到模板/挑战类素材**，只剩 BGM |
| 其余 | 可留空 | 对应类型的查询不生成 |

**换句话说：`主体` + `热点信号词` 是硬门槛，其余都是「填了才有的功能」。**

---

## 十、怎么校验

```bash
python scripts/doctor.py          # 检查词库是否存在、模型层开关
python scripts/plan_queries.py    # 能生成计划就说明词库结构没问题
```

`plan_queries.py` 会在终端打印生成的查询（按类型分组）。
如果打出来是 0 个查询，基本就是 `主体` 为空或字段名拼错了。

另有一个维护脚本 `scripts/build_keywords.py`，用于重建主体和厂牌关系
（需要联网抓公开资料，可选）。
